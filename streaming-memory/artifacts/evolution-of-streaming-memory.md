# The Evolution of Streaming Memory

*Read-this-first overview of how memory for streaming-video LLMs evolved — from a fixed K-means bank in a captioning model to budgeted latent-evidence allocation, agentic month-scale stores, and reasoning that is folded into memory itself.* Part of the [[streaming-memory]] sub-topic under [[streaming-video-understanding]]; siblings: [[proactive-response]], [[streaming-benchmarks]]. Companion artifacts: [[streaming-memory-design-axes]], [[streaming-memory-benchmark-table]], [[streaming-memory-concept-graph]].

## 1. The throughline

Every method here answers one question: **an unbounded video stream cannot fit in a context window, so what do you keep, in what form, and how do you get it back at query time?** The field's arc is a steady move away from *storing everything* toward *storing the right things cheaply*, and — most recently — toward *changing what "remember" even means*. It began (pre-LLM) with a fixed-size clustering bank that made ingest cost constant ([[streamingdvc]]), matured into decoupled bounded memories read on demand ([[flash-vstream]]), then split into two dominant training-free lines once video-LLMs arrived: **retrieve from a full/offloaded KV store** ([[rekv]]) versus **compress the KV cache to a fixed budget** ([[infinipot-v]], [[streammem]]). Around these grew hierarchical/event-structured memories ([[streamforest]], [[fluxmem]]), parametric memories that live in network weights ([[ovg-hq-unify]], [[video-salmonn-s]]), and streaming-aware attention layouts that make the cache itself the memory ([[streamingvlm]], [[hermes-kv]]). The 2026 frontier reframes memory as an **allocation problem** (budgeted latent evidence, [[streaming-model-remember]]), as an **agent's job** (search + tools + month-scale recoverable frames, [[eventmemagent]], [[visual-agentic-memory]]), and as **reasoning to be amortized** — folding streaming chain-of-thought into memory so the query is near-instant ([[vst]], [[tays]], [[tww]]).

## 3. How each idea family evolved

The families below are shared across all four [[streaming-memory]] artifacts. ([[video-salmonn-s]] is grouped with the parametric-memory thread in Family D; it and [[ovg-hq-unify]] are the two "memory-lives-in-weights" methods.)

### A. Budgeted KV compression / eviction
*Hold a fixed KV budget over an unbounded stream, deciding online which tokens to drop.*

**Origin — [[infinipot-v]] (Jun 2025).** The defining move: compress the cache back to a target size `|C|` whenever a budget `|M| >> |C|` is hit, so peak GPU memory is *constant* over an unbounded stream. It scores by two spatiotemporal signals — temporal-axis redundancy on Keys (TaR) and value-norm on Values (VaN) — and is **query-agnostic**, so multi-turn QA needs no re-prefill (unlike query-conditioned SnapKV-style eviction). Verified: 6K vs 50K full cache reaches full-cache accuracy at ~1/8 memory (MLVU 65.8 = 65.8, EgoSchema 65.6 vs 65.2), peak GPU memory cut up to 94% with ~0.5% overhead.

**Refinements.** [[streammem]] (Aug 2025) makes the compression *implicitly* query-shaped without a real question — scoring visual tokens by cross-attention from the model's own **chat-template tokens** as a proxy query, and merging each frame into a weighted prototype; its 24K budget surpasses the full ~50K cache. [[streamingtom]] (Oct 2025) splits the problem by *where* cost lives: Causal Temporal Reduction before the LLM (compute) and Online Quantized Memory — 4-bit, per-group, retrievable KV — after it (memory), cutting a one-hour cache to 1.2 GB vs 18.8 GB. [[streamingassistant]] (Dec 2025) is a sub-millisecond pruner that removes *spatial* redundancy via a checkerboard-masked, parallel-safe pass (max-similarity to 4-connected neighbors, MSSAVT), reusing TimeChat-Online's temporal DTD first. [[decouple-and-cache]] (May 2026, DSCache) diagnoses a *cumulative-effect* recency bias in naive streaming caches and fixes it by decoupling an incrementally-built cumulative cache from an **on-demand instant cache re-encoded from a small raw buffer**, over position-agnostic (pre-RoPE) KV; removing the instant cache drops StreamingBench 79.12 → 74.27, so it is the load-bearing half — while removing the *cumulative* cache barely moves it (79.12 → 79.06). That second number is quietly damning: on these benchmarks most of the incrementally-built history was dead weight, and the real gain is re-encoding the recent window cleanly.

**Frontier — [[omnimem]] (Jun 2026).** Extends budgeted compression to *audio-visual* LLMs: two separate caches with **Audio-Visual Budget Allocation** sizing each modality (and layer) by measured compressibility, and a multiplicative attention × non-redundancy retention score. Removing AVBA (a uniform single cache) costs ~2.8–3.3 points — evidence that *modality-aware* budgeting is the new axis. Lineage: [[omnimem]] cites [[infinipot-v]], [[streammem]], and [[hermes-kv]] as the compressors it beats.

### B. Streaming attention layouts (sink + sliding window; think-while-stream)
*Don't build a separate memory store — shape the attention pattern so the KV cache itself is a well-behaved bounded memory.*

**Origin — [[streamingvlm]] (Oct 2025).** Ports StreamingLLM's attention-sink + sliding-window KV to video, with an asymmetric cache (evict vision first, keep sink + recent text) and **Contiguous RoPE** so positions saturate inside the training length. Its real contribution is closing the train/test gap: an *overlapped-chunk full-attention SFT* teaches the recency bias the cache enforces at inference. Verified: 66.18% win rate vs GPT-4o-mini on infinite streams at O(TW) cost — matching the O(TW²) overlapping window (66.54%), while unaligned full attention collapses to 3.89% — and native-vs-contiguous RoPE is a 25.09% → 66.18% swing. Handle the headline with care: it is scored on the paper's *own* benchmark (Inf-Streams-Eval — sports commentary only, GPT-5 pairwise judge); the transferable evidence is that streaming SFT alone lifts external VQA (+5.96 OVO-Bench Real-Time) with no VQA-specific tuning.

**Refinement / branch — think-while-stream.** [[tays]] (Mar 2026) splits the cache into modality-specific **video and reasoning caches** fused by a zero-copy merge/split loop, so chain-of-thought decodes *concurrently* with frame ingestion (decoupled RoPE axes stop index drift). [[vst]] (Mar 2026) turns the *pre-query playback time* into amortized reasoning: the model emits streaming "thoughts" folded into a **textual** FIFO long-term memory, then answers near-instantly — 79.5 StreamingBench (beats StreamForest-7B 77.3, GPT-4o 73.3) at ~0.56 s query latency vs ~8.80 s for batch CoT (~15.7×). It contrasts *textual* long-term memory against [[flash-vstream]]'s *visual* memory and overtakes [[streamforest]] as open-source SOTA — its OVO Backward-Tracing 56.7 (vs StreamForest's 52.0) is the load-bearing number for "text memory beats visual event memory on retrospective queries." Its ablation also cleanly decomposes what training buys: SFT alone lifts Backward memory (+9.2), RL alone lifts Forward prediction (+12.7). Two caveats: [[tays]]'s near-zero TTFT (9.2e-7 s) is a warm-start decoder-level number (end-to-end delay ~12 s), and at 3B a plain interleaved-SFT baseline ties it on objective accuracy (33.96 vs 33.45) — its edge is subjective win rate (43.7% vs 21.7%) and latency stability.

**Frontier — the parallel-caching trio.** [[tays]], [[vst]], and (in Family D's memory-note style) [[tww]] converge on the same insight: causality-respecting decoupled positional encoding + a dual cache lets a model watch and reason at once. This ties Family B directly into the [[proactive-response]] sub-topic, where *when to speak* is the mirror-image question.

### C. KV / segment retrieval
*Keep the KV (fully, offloaded, or lightly compressed) and, at each question, fetch only the relevant blocks.*

**Origin — [[rekv]] (Mar 2025).** The branch's root: preserve **every** frame's KV (offload the tail to RAM/disk) and, per question, retrieve the top-k relevant blocks by cosine similarity using the Video-LLM's *own attention keys* as the retriever — training-free, graftable onto any decoder Video-LLM. Verified: streaming RVS-Ego/Movie 63.7/54.4 (LLaVA-OV-7B, internal retrieval) beating Flash-VStream-7B (57.3/53.1); internal retrieval nearly doubles relevant-frame recall over external (70.5 vs 58.1; uniform sampling is 6.1). Nearly every later method benchmarks against it. The branch's open wound is in the same table: internal retrieval reaches 56.0 QaEgo4D accuracy vs 64.4 with oracle retrieval — ~8 points of retrieval-quality headroom that no successor has closed.

**Refinements.** [[livevlm]] (May 2025) argues *against* CPU offload — training-free VSB compression + position-decoupled **page retrieval** on a single 24 GB GPU, topping GPT-4o on StreamingBench (63.10 vs 62.50). [[streamkv]] (Nov 2025) unifies compress-and-retrieve into one **layer-adaptive** SelectKV module: compress once with a question-agnostic guidance prompt (enables multi-turn), retrieve with the real question — +5.4 over ReKV while discarding 60% of the cache, and the semantic-vs-uniform partitioning gap *widens* under compression (+5.31 at ↓90%). [[cacheflow]] (Nov 2025) prunes temporally-redundant tokens online, packs survivors into fixed 196-token blocks indexed by a frozen GRU, offloads full KV to CPU, and rehydrates only Top-K **consensus**-retrieved blocks — matching/beating ReKV while dropping up to ~87% of tokens at 2.9 GB. [[rlivs]] (Oct 2025) is the *recurrent* variant: keep 196 of 3,136 tokens per clip (selected by the backbone's caption→visual cross-attention), carry them through a FIFO memory, and answer from MMR-retrieved *captions* rather than reprocessing frames — new RVS SOTA (65.3/57.7 vs ReKV 63.7/54.4). It is essentially [[videostreaming]] rebuilt without training (the note's own lineage: the training-free, attention-selected counterpart) — a neat closure of the 2024 trained-memory line.

**Frontier — [[v-rex]] (Dec 2025).** Pushes retrieval to hardware co-design: hash-bit LSH key clustering + a weighted cumulative-sum threshold (WiCSum) that adapts token selection per layer/head (replacing fixed top-k), paired with an edge accelerator for 2.2–7.3× per-frame speedup and ~3× fewer tokens than fixed-top-k ReKV at matched accuracy. Lineage across C is explicit: [[livevlm]], [[streamkv]], [[cacheflow]], [[rlivs]], and [[v-rex]] all name [[rekv]] as the baseline they improve on.

### D. Hierarchical & event-structured memory (and parametric memory)
*Give memory explicit structure — granularity tiers, event trees, or weights — so history is compressed without being flattened.*

**Ancestors.** [[streamingdvc]] (Apr 2024, pre-LLM) supplies the two reusable ideas: a fixed-size K-means memory (constant ingest cost) and streaming decoding points with past captions fed back as prefix — its ablation shows the prefix is essential (no-prefix collapses ActivityNet CIDEr 40.6 → 23.1), and its memory comparison is the first evidence that *how* you compress matters more than *that* you compress: clustering holds CIDEr 30.6 at 64 frames while EMA collapses to 22.0. [[videostreaming]] (May 2024) moves streaming encoding into a trainable LM producing a constant question-selected memory; [[videollamb]] (Sep 2024) carries a fixed memory-token pool recurrently across scene segments with a retrieval cache.

**Origin of bounded structured memory — [[flash-vstream]] (Jun 2024).** The template for "bounded memory read on demand": a four-granularity **STAR** memory (spatial FIFO, temporal K-means clusters, abstract semantic-attention, retrieved raw frames) capped at 681 tokens, plus an async single-writer / on-query-reader design giving flat ~1 s latency and ~16 GB regardless of stream length. That two-process split is the family's most-inherited (and least-credited) contribution: it reappears as [[streamchat-mem]]'s three parallel threads, [[visual-agentic-memory]]'s decoupled indexer/agent, and [[tays]]'s parallel caches.

**Refinements — tiers, trees, and text.** [[streamchat-mem]] (Jan 2025) makes the store a *tree* of k-means visual clusters indexed by text clues, with an Ebbinghaus-weighted short-term slot and a separate FAISS dialogue memory. [[videoscan]] (Mar 2025) compresses to one carrier token per frame; [[providellm]] (Apr 2025) verbalizes the long-term past into text while keeping the present visual. [[streamforest]] (Sep 2025) is the event-tree apex: a bounded **Persistent Event-Memory Forest** whose nodes merge under similarity / merge-count / temporal penalties, beside a sharp real-time window. [[videoscaffold]] (Dec 2025) grows an *elastic* event tree online by prediction-error segmentation, consolidated bottom-up at query time. [[fluxmem]] (Mar 2026) makes a three-tier short/mid/long cascade **parameter-free** via per-frame Otsu-adaptive thresholds (no manual drop ratio) — and, notably, reuses its retention statistics as a zero-cost proactive-response trigger. [[weavetime]] (Feb 2026) adds an orthogonal ingredient: teach *temporal order* (a training-time shuffle-reconstruction loss) and *use* it via an uncertainty-triggered coarse-to-fine recall cache.

**The KV-as-hierarchy convergence — [[hermes-kv]] (Jan 2026).** Collapses "structured memory" and "KV cache" into one: the decoder's KV cache *is* a layer-stratified memory (shallow = sensory/recency, middle = working, deep = long-term/anchors), evicted by layer-matched importance — retrieval-free, with no query-time compute (10× faster TTFT than StreamingTOM, constant ~16.5–17.7 GB from 16–512 frames). [[eventmemagent]] (Feb 2026) and [[tww]] (Mar 2026) sit at this family's agentic/reasoning edge: the former searches an event-segmented memory with tools; the latter writes one compact **text note per segment** and answers over the notes under a strict streaming mask (removing the notes drops it 57.40 → 52.35).

**Parametric-memory thread.** [[ovg-hq-unify]] (Aug 2025) and [[video-salmonn-s]] (Oct 2025) share the boldest idea in the family: **store history in weights**. OVG-HQ-Unify's Parametric Memory Block updates a small network's parameters one gradient step per timestep via self-supervised reconstruction (fixed footprint, PMB overhead only 2.20 ms). video-SALMONN-S puts long-term memory in the *fast weights* of a test-time-trained MLP (reconstruction + long-span prediction loss) with a prompt-dependent reader, handling 3-hour audio-visual streams and beating token-bank baselines by ~15% on ELViM. This thread is the conceptual bridge to Family F's "what should a model remember at all."

### E. Agentic / semantic memory
*Treat memory as an explicit, searchable, semantically-structured store an agent (or a semantic prior) queries — not a token/KV heap.*

**Origins.** [[cogreasoner]] (Jun 2025) reframes streaming QA as *context selection* — an explicit LLM "Select" step retrieves only relevant history QAs and dual-compresses events by relevance — and ships CogStream; verified retrieved-context 72.26 beats all-context 70.48 and stays robust under distractors (~71.94 while an all-context baseline drops −4.72). [[savemem]] (May 2026) injects a fixed 5-probe **pseudo-question** semantic prior into three-tier compression plus an anchor-conditioned recency gate, becoming the best training-free method on OVO-Bench 7B (62.69 vs FluxMem 57.22, HERMES 59.20).

**Refinements — memory as a graph.** [[streammeco]] (Apr 2026) compresses an *agent memory graph* (M3-Agent) by connectivity — diversity sampling for isolated nodes, importance+redundancy pruning for connected nodes — plus time-decay retrieval, restoring/exceeding baseline at 70% compression (45.7% vs 44.7%) with 1.87× retrieval speedup. Read the attribution carefully: compression alone at 70% *loses* points (44.7 → 41.2); the time-decay retrieval rule does all the accuracy work, so the billing as a "compression layer" undersells where the win lives.

**Frontier — full agents.** [[eventmemagent]] (Feb 2026; also structurally in D) trains a ReAct agent via GRPO to search event-segmented memory and call OCR/detection tools, matching GPT-4o on OVO-Bench (60.75 vs 59.54) with ≤32 frames — though its own ablations show the memory *structure* it is named for is a small lever (−0.59 OVO) next to the tools (−3.88 detection, −2.87 OCR): active fine-grained perception, not memory partitioning, carries the result. [[visual-agentic-memory]] (May 2026, VAM) decouples online indexing from a query-time MLLM agent that plans, retrieves temporally+spatially, and **inspects raw frames** before a cited answer — evidence-preserving rather than compressed-away — running a 105.6-hour / 51-day stream while storing 6,876 frames (0.06% of raw, ~1659× fewer). Handle with care: no ablation table isolates its cascade, and on month-scale MM-Lifelong it is edged by ReMA+GPT-5 (17.62 vs 17.11) while humans score 82.5% — a >65-point gap that defines the open problem more than any method solves it. [[streamvln]] (Jul 2025) is the *embodied* member: a streaming VLN agent whose SlowFast context pairs a KV-reused sliding window with a slow memory compressed by voxel-based 3D-aware pruning — memory as spatial state, not just tokens — and its memory-size ablation lands a counterintuitive punch: the pruned 8×196 memory *beats* keeping all context (SR 45.5% vs 40.0%), forgetting acting as regularization.

### F. Principled selection — what to remember at all
*Step back from mechanism to the objective: formalize memory as a budgeted allocation and learn the write/keep/read policy.*

**[[streaming-model-remember]] (Jun 2026, SelectStream).** The family's sole (and culminating) member reframes streaming memory as **budgeted online latent-evidence allocation**: the *current* frame stays raw to a frozen VLM while history is exposed only through a small, query-conditioned **evidence budget**, governed by three decoupled budgets — `N` (capacity), `B` (retrieval subgraph), `M` (injected evidence) — over a fixed-capacity latent memory graph. It separates *when to write* (surprise windowing), *what to keep* (priority-protecting consolidation), and *how to read* (graph-attention reasoning). Verified: 82.67% StreamingBench (Qwen3-VL-8B) and 67.03% OVO-Bench, with the biggest gains on history-dependent Backward-Tracing (BT Avg 54.00 → 62.20) while real-time perception stays high — exactly what a *principled* keep-the-right-history policy should produce. Ablating the adaptive segmentation (fixed segments) drops it 81.42 → 79.86, and it beats memory-bank baselines including [[hermes-kv]] and [[streamforest]]. This is the theoretical mirror of the mechanism families: A–E ask *how* to compress/retrieve; F asks *what a stream is worth keeping*.

## 4. Convergence & cross-pollination

Three strong currents pull the families together:

- **KV cache = memory.** Families A, B, C, and D are converging on the KV cache as the *single substrate*. Compression (A) and retrieval (C) are increasingly the same module — [[streamkv]] literally shares one layer-adaptive selector for both, and [[hermes-kv]] dissolves retrieval entirely by treating the layered KV cache as the memory. [[decouple-and-cache]] and [[streamingtom]] show compression stacks composably with retrieval. Meanwhile the attention-layout line (B) argues the cache needs *no* separate store if training is aligned to a sink+window pattern ([[streamingvlm]]).

- **Query-agnostic vs query-conditioned, then both.** An early fault line — store-all-then-retrieve-per-query ([[rekv]]) vs compress-once-query-agnostic ([[infinipot-v]], [[streammem]]) — has resolved into hybrids that compress query-agnostically (for multi-turn reuse) and retrieve query-specifically: [[streamkv]], [[cacheflow]], [[savemem]]. The pseudo-query / proxy-query trick ([[streammem]], [[savemem]]) is the connective idea that lets query-agnostic memory behave as if it knew the question. The two sides' own ablations quietly settle the fight with a resolution no paper states outright: **the query matters enormously for reading, marginally for writing.** [[rekv]]'s recall ladder (uniform 6.1% → external 58.1% → internal keys 70.5%) shows query-conditioned *retrieval* is worth tens of points, while [[streammem]]'s proxy-vs-oracle gap (66.9 vs 68.1 MLVU) shows knowing the true question is worth only ~1.2 points for *eviction scoring*. [[streamkv]] operationalizes exactly this split — query-agnostic compression, query-specific retrieval — without claiming the general principle.

- **Memory absorbs reasoning and time.** The newest move is that memory is no longer passive. Reasoning is folded *into* it ([[vst]], [[tays]], [[tww]]), temporal order is trained *into* it ([[weavetime]]), and events are the atomic unit across [[streamforest]], [[videoscaffold]], [[eventmemagent]], and [[visual-agentic-memory]]. Parametric memory ([[ovg-hq-unify]], [[video-salmonn-s]]) and principled allocation ([[streaming-model-remember]]) push memory from a data structure toward a *learned policy*.

**Shared primitives the field reinvents but never compares.** Beneath the family boundaries, three mechanisms recur so often they amount to an unacknowledged common toolkit — and none has a controlled head-to-head:

- **Position-agnostic ("virtualized") KV.** Storing or scoring KV independently of RoPE positions and re-injecting positions at use time is independently reinvented across at least seven papers: [[rekv]] re-indexes retrieved KV as consecutive tokens, [[livevlm]] strips RoPE before page scoring and restores it after, [[cacheflow]] offsets positions on rehydrated blocks, [[decouple-and-cache]] stores pre-RoPE KV (its Prop. 4.2 is the only *formal* treatment — shifted-but-relative-distance-preserving IDs give identical outputs), [[streamingvlm]] uses contiguous RoPE, and [[tays]] / [[tww]] decouple positional axes for input vs output streams. Where an ablation exists it is enormous ([[streamingvlm]]: 25.09% → 66.18%), yet no paper names "position-virtualized KV" as the shared abstraction.
- **Cosine-similarity redundancy dropping.** The same primitive under many thresholds: per-patch vs previous frame ([[cacheflow]], τ=0.5), on Keys along the temporal axis ([[infinipot-v]] TaR), input-frame filtering ([[streammem]], δ=0.95), spatial 4-connected neighbors ([[streamingassistant]]), Otsu-adaptive ([[fluxmem]], [[visual-agentic-memory]]). Only [[fluxmem]] removes the manual threshold; only [[savemem]] argues the primitive itself is semantically blind. Nobody has published a controlled comparison of the primitive.
- **Event segmentation, ~5 ways, never head-to-head.** Optical-flow frame gating ([[streamchat-mem]]), adjacent-frame cosine threshold ([[streamkv]], θ=0.99), next-frame prediction error ([[videoscaffold]]), grayscale-histogram Pearson correlation ([[eventmemagent]], δ=0.2), and attention-JS-divergence + feature-change surprise ([[streaming-model-remember]]). A cheap, decisive ablation paper — one backbone, one budget, all boundary detectors — is sitting here unwritten.

**Links into sibling sub-topics (real, not nominal):**
- **→ [[proactive-response]]:** [[fluxmem]] reuses its memory-retention statistics as a zero-overhead *proactive trigger*; the watch-while-think trio [[vst]] / [[tays]] / [[tww]] make *when to answer* and *what to keep* the same decision, and cite the proactive-response ancestors (VideoLLM-online, Dispider) as baselines. The same signal (redundancy/surprise) increasingly serves both *what to keep* and *when to speak* — yet no paper trains the two objectives jointly.
- **→ [[streaming-benchmarks]]:** the memory line is measured almost entirely on the benchmark line — StreamingBench, OVO-Bench (esp. its history-dependent Backward-Tracing split, which is the memory stressor), and RVS/VStream-QA. [[streamchat-mem]] and [[streamforest]] *ship* their own benchmarks (StreamBench, ODV-Bench), and [[cogreasoner]] ships CogStream — memory methods increasingly co-design the eval that exposes forgetting. The eval substrate also *migrated* (RVS/VStream-QA for the 2024–early-2025 wave → StreamingBench + OVO-Bench for everything after ~Sep 2025), making pre- and post-migration methods longitudinally hard to compare.

**Reading the numbers — comparability caveats.** "Same benchmark" rarely means "same protocol": [[videoscaffold]]'s StreamingBench real-time 41.0 (0.5 fps, Vicuna-7B era) sits beside contemporaries' 75–80 on stronger backbones, and the current top scores differ by less than a backbone generation — [[streaming-model-remember]] 82.67 on Qwen3-VL-8B vs [[decouple-and-cache]] 82.32 on Qwen2.5-VL-7B. Many claimed method-gains are within backbone-upgrade noise; treat cross-paper deltas as directional unless backbone, fps, and budget match.

## 5. Where the field is going (grounded in the 2026 frontier)

The 2026 papers point in five concrete directions:

1. **From heuristics to learned allocation.** [[streaming-model-remember]] (Jun 2026) is the clearest signal: decoupled write/keep/read budgets with a *learned* policy, current-frame-raw + history-as-evidence. Expect the mechanism families (A–E) to be re-derived as special cases of a budgeted objective, and expect surprise/uncertainty-gated writing ([[weavetime]], [[streaming-model-remember]]) to become standard.

2. **Memory that reasons.** [[vst]], [[tays]], [[tww]] (all Mar 2026) establish that *pre-query playback time is free compute* — amortize chain-of-thought into a compact (often textual) memory so the answer is near-instant. This collapses the memory/reasoning/proactive-response boundary and is likely the dominant thread of the next year.

3. **Agentic, recoverable, month-scale.** [[visual-agentic-memory]] (May 2026) and [[eventmemagent]] (Feb 2026) move from *lossy compression* to *searchable, tool-augmented, frame-recoverable* stores that operate at 51-day scale. The design value shifts from "smallest cache" to "provable recall + citation," with GRPO/agent training rather than SFT.

4. **Modality-complete memory.** [[omnimem]] (Jun 2026) and [[video-salmonn-s]] (Oct 2025) extend budgeting and parametric memory to *audio-visual* streams with per-modality budgets — the frontier is no longer vision-only, matching the [[streaming-benchmarks]] shift toward omni-source evaluation.

5. **Weights as memory.** The parametric/test-time-training thread ([[ovg-hq-unify]], [[video-salmonn-s]]) offers the only truly *stream-length-independent* footprint by absorbing history into fast weights. If TTT stability holds at scale, this competes directly with the KV-as-memory convergence — the open question for 2026–2027 is whether the field's substrate is the KV cache or the weights. A conspicuous gap: nobody has hybridized the two — no method indexes *into* parametric memory or backs fast weights with a recoverable store; the substrates are treated as rivals, not layers.

One further blind spot cuts across all five: almost everyone equates memory with *visual* history. Only [[streamchat-mem]] (dialogue memory) and [[cogreasoner]] (retrieved history QAs — 72.26 vs all-context 70.48, robust under distractor turns) treat past *interaction* as first-class memory — untenable for the multi-turn assistants these systems claim to serve.

The consistent pressure across all five is the same one that opened the field: **keep the right things, cheaply, and get them back when the question arrives** — now answered less by clever eviction rules and more by learned policies, agentic search, and reasoning amortized into the memory itself.
