# Eyes Wide Open: Ego Proactive Video-LLM for Streaming Video

**Lineage role:** A NeurIPS 2025 egocentric proactive-streaming contribution that ships both a benchmark (ESTP-Bench) *and* a model (VideoLLM-EyeWO); it reframes proactive responding as a *just-in-time* decision problem — answer only when the visual stream is "ready", neither early nor late — and fills that gap with a data engine + multi-stage training + KV-cache compression.

## Problem — what was limited before this paper (short)
Prior streaming Video-LLMs (e.g. [[videollm-online]], [[mmduet]]) and their benchmarks judge proactivity too loosely: they treat "did the model speak" as binary and ignore *when* it speaks relative to when the answer actually becomes visible in the egocentric stream. Three coupled properties were unmeasured/unsupported: (1) **proactive coherence** — answering questions whose evidence only arrives in *future* frames while staying consistent across a multi-turn dialogue; (2) **just-in-time responsiveness** — firing exactly when the visual evidence is ready, not prematurely and not late, and only when a response is warranted; (3) **synchronized efficiency** — perceiving and answering in sync without lag on a long egocentric stream. Existing eval frameworks could not jointly score these.

## Key idea — the core insight
Treat a streaming assistant as choosing, at every timestep, among *three* actions rather than the usual binary silence/respond. The added action is "ask for a high-resolution frame" — a proactive probe the model triggers when it is *uncertain* whether the current low-res observation is enough to answer. The paper couples this with (a) **ESTP-Gen**, a three-stage data engine that synthesizes multi-turn QA with *multiple valid answer intervals* per question, (b) a **multi-stage curriculum** that grows the model from passive interval-responsiveness → proactive high-res probing → multi-turn coherence, and (c) **proactive dynamic compression** that squeezes the KV cache ~10x by keeping only response-relevant (high-res) tokens at full rate.

## Method + math

### Benchmark: ESTP-Bench (the eval protocol)
**Task taxonomy — 3 proactive types, 14 task types.**
- **Explicit Proactive (8):** Object Recognition, Attribute Perception, Text-Rich Understanding, Object Localization, Object State Change, Ego Object Localization, Ego Object State Change, Action Recognition — answerable by directly reading current visual evidence.
- **Implicit Proactive (4):** Object Function Reasoning, Information Function Reasoning, Next Action Reasoning, Task Understanding — require inference beyond the immediate frame.
- **Contextual Proactive (2):** Object Relative Context, Task Relative Context — require memory of dialogue history + visual coherence.

**Data construction.** Sourced from the **Ego4D validation set**: 890 videos, 100+ scenes (indoor cooking/cleaning, workspaces, public areas). Two-step annotation — MLLM/LLM auto-generation then human verification by two annotators who mark clear interval boundaries by object completeness in-frame. Final eval set: **2264 verified QA instances**, each with an average of **3.96 valid answer intervals**. About **46%** of questions are contextually linked (depend on a prior turn). The training corpus (ESTP-IT) generated by ESTP-Gen: ~**60K single-turn + 20K multi-turn** questions.

**Metric — ESTP-F1.** A prediction counts only if its timestamp lands inside a designated valid window; predictions are grounded to intervals *before* answer quality is scored. The score integrates answer correctness and timeliness against ground-truth items $g_k$:

$$\text{ESTP-F1}=\frac{2\sum_{k=1}^{M} S(g_k)}{2\sum_{k=1}^{M} S(g_k) + \text{FP} + \text{FN}}$$

where $M$ is the number of ground-truth items; $S(g_k)$ aggregates an LLM-judged **answer-quality** term $\mathcal{S}_{\text{answer}}(\hat{o}_l, o_k)$ and a **timeliness** term $\mathcal{S}_{\text{time}}(\hat{t}_l, g_k)$ (in-window response); **FP** are temporal-precision violations (responses outside any valid window) and **FN** are missed response opportunities. This is a temporally-grounded F1: precision punishes speaking at the wrong time, recall punishes silence when an answer was due.

### Model: VideoLLM-EyeWO (the mechanism)
Same backbone/architecture family as [[videollm-online]] (a SigLIP visual encoder + LLaMA3 LLM), fine-tuned with **LoRA**. The key change is the **ternary action space** $A=\{a_{\text{silence/continue}},\, a_{\text{response}},\, a_{\text{ask\_high}}\}$ instead of binary. Given a streaming video and queries $\{(q_i, t_{q_i})\}$, at each timestep $t$ the model picks

$$A_t = \arg\max_{a\in A} P_\theta(A_t = a \mid q_i, O_t, H_t)$$

with observation $O_t$ and history $H_t$.

**Stage-1 — passive interval responsiveness.** Over valid answer intervals $[s,e]\in\mathcal{T}_{\text{interval}}$, use *weighted degree* supervision (not hard binary) so response probability ramps within the interval:

$$\mathcal{L}(t)=\begin{cases}-\log\!\Big(f\!\big(\tfrac{|t-e|}{|s-e|}\big)\cdot P_\theta(a_{\text{response}}\mid q_i,O_t,H_t)\Big)+\omega\,\mathcal{L}_{\text{LM}}(t) & \exists[s,e]\in\mathcal{T}_{\text{interval}},\ t\in[s,e]\\[4pt] -\log P_\theta(a_{\text{continue}}\mid q_i,O_t,H_t) & \text{otherwise}\end{cases}$$

$f$ is a linear-decrease weighting factor on the response-probability loss; $\mathcal{L}_{\text{LM}}$ is the language-modeling loss for the emitted answer, weighted by $\omega$.

**Stage-2 — proactive just-in-time responsiveness.** Introduce $a_{\text{ask\_high}}$: during uncertain timesteps $\mathcal{T}_{\text{uncertain}}$ the model requests the high-resolution frame $O_t^h$ of the current observation:

$$\mathcal{L}_{\text{ask\_high}}(t)=\begin{cases}-\log\!\Big(f\!\big(\tfrac{|t-e|}{|s-e|}\big)\cdot P_\theta(a_{\text{ask\_high}}\mid q_i,O_t,H_t)\Big) & t\in\mathcal{T}_{\text{uncertain}}\\[4pt] -\log P_\theta(a_{\text{continue}}\mid q_i,O_t,H_t) & \text{otherwise}\end{cases}$$

then, conditioned on the extra high-res frame $O_t^h$, decide whether to respond:

$$\mathcal{L}_{\text{determine}}(t)=\begin{cases}-\log P_\theta(a_{\text{response}}\mid q_i,O_t,H_t,O_t^h)+\omega\,\mathcal{L}_{\text{LM}}(t) & t\in\mathcal{T}_{\text{timestamp}}\\[4pt] -\log P_\theta(a_{\text{continue}}\mid q_i,O_t,H_t,O_t^h) & \text{otherwise}\end{cases}$$

with total $\mathcal{L}(t)=\mathcal{L}_{\text{ask\_high}}(t)+\mathcal{L}_{\text{determine}}(t)$.

**Stage-3 — multi-turn coherence.** Train only on multi-turn questions to strengthen contextual/dialogue-history consistency while preserving the responsiveness learned earlier.

**Proactive dynamic compression.** A special compression token $\langle ct\rangle$ is inserted after a segment; causal self-attention folds the preceding segment into the KV cache. **Two-level** rates: question-relevant / high-res content is compressed lightly, other content heavily; once a response is emitted the preceding context collapses toward a single token. Net effect: average token usage ~1/10 of the raw sequence.

## Explicit design choices
- **Ternary action space** {silence/continue, response, ask_high} — the "ask_high" probe is the mechanism for just-in-time responding under uncertainty.
- **Two-resolution frame budget:** stream perceived at low resolution by default; high-resolution frame $O_t^h$ fetched only when the model actively requests it, keeping compute low.
- **Interval (not point) supervision** with a linear-decrease weighting $f(\cdot)$ — avoids the over-extend/under-respond trade-off caused by binary labels on near-identical adjacent frames.
- **Multiple valid answer intervals per question** (avg 3.96) — reflects that in streaming there is no single correct answer moment.
- **Three-stage curriculum** (passive → proactive high-res → multi-turn) rather than single-stage training, to avoid the training conflict of near-duplicate streaming frames.
- **ESTP-Gen data engine:** one-to-one (caption/QA extraction) → one-to-many (RAG expands to multiple valid intervals) → many-to-many (compose coherent multi-turn dialogues).
- **KV-cache compression** with special $\langle ct\rangle$ tokens and two-level rates keyed to response relevance; collapse context after each answer.
- **LoRA fine-tuning** on a VideoLLM-Online-style SigLIP+LLaMA3 backbone (no full retrain).
- **Temporally-grounded ESTP-F1** metric that jointly scores answer correctness, timeliness (in-window), false positives (wrong-time speech) and false negatives (missed answers).

## Key results / what to remember
Verified against the paper's tables (arXiv v1).
- **ESTP-Bench overall (Table 2):** VideoLLM-EyeWO **34.7** overall vs MiniCPM-V (offline polling) 22.9, MMDuet 17.8, LIVE (thr=0.9) 15.5. Reported as **+19.2%** over the VideoLLM-Online baseline and **+11.8%** over the best offline MLLM.
- **Per-type (Table 2):** Explicit Proactive **23.6**, Implicit Proactive **52.5**, Contextual **43.6**; task highlights — Object Localization 26.8, Next Action Reasoning 75.3, Task Understanding 78.7.
- **Cross-domain generalization (Table 3):** OVO-Bench online avg **24.16** vs VideoLLM-Online **8.05**; QAEGO4D offline **36.20** vs **29.80**.
- **COIN top-1 accuracy (Table 4):** Step **93.3** (+0.7), Task **51.1** (+1.4), Proc+ **55.5** (+1.9) over VideoLLM-Online 8B+.
- **Ablation (Table 5):** single-question ESTP-F1 climbs LIVE 14.9 → +ESTP-IT 22.0 → Stage-0 24.9 → +ask_high 34.0; contextual climbs 18.9 → 25.7 → 23.0 → 38.7 → **43.6** (final). KV cache **9636 → 942 tokens (~99% reduction)**; 3242.8 with contextual questions.

Takeaways: (1) proactive streaming is best modeled as a *timing* decision, and an explicit "ask for more detail" action is a clean lever for just-in-time answering; (2) interval-weighted supervision + a staged curriculum resolves the binary-label training conflict that hurts VideoLLM-Online-style models; (3) the temporally-grounded ESTP-F1 (with FP=wrong-time, FN=missed) is a reusable metric design for any proactive-response benchmark; (4) response-keyed KV compression buys ~10x memory with maintained accuracy.

## Open questions / limitations
- The "ask_high" action assumes a two-resolution frame source is available and cheap to fetch on demand; latency/cost of that fetch on a real device stream is not deeply quantified.
- ESTP-Bench is built solely from Ego4D validation videos — egocentric, ~100 scenes; generalization of the *metric* and *timing* behavior to non-ego streaming is untested here.
- Answer quality relies on an LLM judge ($\mathcal{S}_{\text{answer}}$), inheriting judge bias/variance; the timeliness window boundaries come from human interval annotations that are inherently fuzzy.
- The ternary action + staged curriculum adds training complexity; ablation shows Stage-2 sometimes trades single-question score (34.0 → 33.2) for contextual gains — the balance is delicate.
